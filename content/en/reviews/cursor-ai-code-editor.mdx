## Why an AI-first editor deserves its own review

Traditional editors treat AI as an add-on: a sidebar you consult. Cursor inverts that — the editing model itself assumes an AI collaborator. That distinction sounds like marketing until you notice where the friction actually lives: not in generating code, but in giving the assistant enough context to be useful across a whole project.

This review is organized around that question: does the AI-first model change daily work, or only the demo video?

## The editing model in practice

Three behaviors define the experience:

1. **Repository-wide context.** Suggestions reference files you never opened. In a real project this is the difference between a snippet generator and a collaborator.
2. **Multi-file edits.** Requests like "rename this concept across the codebase" become guided operations rather than search-and-replace archaeology.
3. **Conversation anchored to code.** Discussions attach to specific lines, so context survives between sessions.

## Where it adds friction

The model has costs. The subscription gates the best capabilities. Cloud processing raises legitimate policy questions for teams handling sensitive code. And context is not magic: on unfamiliar domains the assistant still guesses, which means review discipline matters more, not less.
